# Требования к шаблону «Страница фич» (Roadmap slide)

> Документ для дизайнера. Один шаблон используется для автоматической генерации
> слайда-роадмапа со списком фич по кварталам. Программа сама клонирует колонки и
> подставляет данные — дизайнеру нужно один раз сверстать «одну колонку» и подписать
> фигуры точными именами.

## 1. Что это за слайд

Это контентный слайд роадмапа: сверху название тира/продукта, ниже — колонки по
кварталам (Q1, Q2, Q3, Q4…), в каждой колонке список фич. Один и тот же шаблон
покрывает все случаи: 1, 2, 3, 4 и более кварталов, переполнение и продолжение
на следующий слайд.

## 2. Технические параметры

- Формат: `.pptx`.
- Соотношение: **16:9** (ширина 13.333″ × высота 7.5″; в PowerPoint — 1920×1080 pt).
- В файле достаточно **одного слайда** — программа берёт первый слайд, где есть
  нужные именованные шейпы.

## 3. Обязательные именованные шейпы

Нужно дать фигурам **точные английские имена** (регистр важен):

| Имя | Тип | Назначение | Что подставляет программа |
|---|---|---|---|
| `eyebrow` | текст | маленький ярлык над заголовком | «Roadmap» / «Roadmap (cont.)» (или RU-вариант) |
| `slide_title` | текст | заголовок слайда | название тира/продукта |
| `col_header` | фигура/текст | **один** заголовок квартала (прототип) | «Q1 2025», «Q2 2025» … |
| `col_bullets` | текст | **один** список фич (прототип) минимум с двумя абзацами | первый абзац — стиль AppTitle, второй — стиль фичи |
| `Product_Name` | текст | название продукта | исходное имя Product |
| `quarter_marker` | фигура | **одна** точка квартала (прототип) | клонируется над каждым `col_header` |

**Заголовки групп фич (AppTitle) программа рисует жирным абзацем внутри
`col_bullets`** — отдельный шейп не нужен.

**Имена должны быть уникальными** в пределах слайда. Нельзя называть несколько
фигур одинаково (например, два `col_bullets`) — программа берёт один прототип
колонки, а остальные фигуры с тем же именем попадут в слайд как есть.

Как переименовать фигуру в PowerPoint: выделить → «Главная» → «Упорядочить» →
«Область выделения» (Alt+F10) → двойной клик по имени в списке.

## 4. Служебные шейпы — не отображаются

Фигуры, которые не должны попадать в сгенерированный слайд (направляющие линии,
подписи для себя, примеры содержания), называются с **префиксом `_`** в начале
имени. Программа не копирует такие шейпы в результат.

| Имя шейпа | Судьба в сгенерированном слайде |
|---|---|
| `col_bullets`, `logo`, `line` | копируются |
| `_guide`, `_sample`, `_slide_number` | **не копируются** |

Это удобно, когда дизайн слайда удобнее верстать поверх направляющих/заглушек:
оставляете их в файле, но помечаете `_`, и в генерации их не будет.

## 4. Принцип «одна колонка-прототип»

Дизайнер верстает **одну колонку** (шапка `col_header` + список `col_bullets` + при необходимости `quarter_marker`),
расположенную у левого края. Программа сама:

- клонирует эту колонку под каждый квартал;
- расставляет колонки слева направо с зазором ≈0.25″;
- подставляет данные (кварталы и фичи).

**Требования к колонке:**

- Точки привязки логических слотов расставляет программа. Ширина и высота
  `col_header`/`col_bullets` сохраняются ровно как в шаблоне.
- Первый абзац `col_bullets` задаёт формат заголовка AppTitle, второй абзац —
  формат строки фичи. Заголовок рекомендуется делать крупнее фичи.
- `col_header` может быть уже (плашка/пилюля), но его левый край должен совпадать
  с левым краем `col_bullets`.
- `quarter_marker` размещается над первым `col_header`; его относительное
  положение сохраняется у всех клонированных кварталов.
- Высота `col_bullets` — до нижней части слайда, оставив ~0.4″ снизу под сноску.
  Вместимость колонки рассчитывается по высоте текста (перенос строк), а не по числу фич.

## 6. Форматирование — критично

Программа при подстановке текста **копирует формат первой строки** шейпа
(шрифт, размер, цвет, жирность). Поэтому:

1. **Цвет текста — явный RGB**, а не «цвет темы» (Theme/Scheme Color). Иначе при
   генерации цвет слетает — это частая причина «белое на белом».
2. **Заливка/контур фигур — явный цвет**, не из темы.
3. **Контраст обязателен**: тёмный текст на светлом фоне (или светлый на тёмной
   заливке). Никакого белого-на-белом.
4. **Шрифт**: явное имя + размер (программа сохранит шрифт первой строки).
5. **Текст-заглушка** в каждом шейпе с финальным форматированием, например:
   - `col_header` → «Q1 2025»;
   - `col_bullets` → «• фича» (одна строка; маркер «•» программа добавляет сама —
     достаточно обычного текста без встроенных списков).
6. **Фон слайда задать явно** (обычно белый или светло-серый), не полагаться на тему.

## 7. Что делать НЕ нужно (программа добавит сама)

- Не верстать 4 готовые колонки — программа клонирует одну.
- Не рисовать сноску «* Subject to Change» — она добавляется автоматически внизу.
- Не вписывать название тира статичным текстом — оно подставляется в `slide_title`.
- Не класть картинки (логотипы) внутрь групповых фигур, которые редактируются
  программой — надёжнее отдельными шейпами.

## 8. Чек-лист для сдачи шаблона

- [ ] 16:9, один слайд.
- [ ] Шейпы названы точно: `eyebrow`, `slide_title`, `col_header`, `col_bullets`.
- [ ] Имена шейпов уникальны (не два `col_bullets`).
- [ ] Служебные/направляющие шейпы помечены префиксом `_`.
- [ ] Одна колонка-прототип (header + bullets), ширина bullets 2.5–2.9″.
- [ ] Все цвета/заливки/шрифт — явные (не Theme).
- [ ] Текст-заглушка с финальным форматированием.
- [ ] Текст контрастный (не белое-на-белом).

## 9. Как проверить

Готовый `.pptx` загружается в приложение в разделе «Библиотека шаблонов» →
«Загрузить шаблон» → «Сделать активным». Приложение покажет, какие обязательные
шейпы найдены/отсутствуют, и сгенерирует PNG-превью первого слайда.
