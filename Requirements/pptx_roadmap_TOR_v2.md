# ТЗ v2: генератор pptx-роадмапов из JSON (финализировано по ответам)

## 1. Зафиксированные правила

| Параметр | Решение |
|---|---|
| Вместимость колонки | Динамическая, зависит от длины текста фичи (перенос строк) |
| Число колонок (слотов) на слайде | Базовая сетка — ровно 4 слота; для простого однослайдового roadmap действует адаптивное заполнение ширины (см. §3) |
| Сжатие колонок | Запрещено; адаптивный режим только расширяет 1–3 используемые колонки |
| Окно роадмапа | Год = 4 квартала (q1–q4), число кварталов не варьируется |
| Заголовок квартала при расщеплении | Не дублируется и не мерджится — отображается только в первом под-слоте квартала, у остальных под-слотов шапка пустая |
| Лимит под-колонок на квартал | Не ограничен |
| Группировка фич | По полю AppTitle (продукт); группа не может быть разорвана между под-колонками |
| Порядок фич внутри квартала | Строго по порядку в JSON (без пересортировки по приоритету/дате) |
| Перенос при переполнении слайда | Переносится квартал целиком (не "хвост") |
| Слайд-продолжение | Содержит только таблицу, без заголовка роадмапа/легенды |
| Шаблон | pptx с именованными шейпами-плейсхолдерами, движок ищет их по имени |
| Длинный текст в ячейке | Перенос строки, высота строки растёт, вместимость колонки соответственно падает |
| Кастомные цвета/иконки по статусу | Не требуются |

## 2. Модель данных

```
Feature {
  app_title: str      // продукт, группировка
  name: str            // текст фичи
  quarter: int         // 1..4
  order_index: int     // порядок в исходном JSON (сохраняем как есть)
}
```

Входной JSON — плоский список Feature, порядок в массиве = порядок отображения. Группировка по `app_title` определяется соседними записями с одинаковым значением (группа = набор идущих подряд Feature с одинаковым app_title в пределах одного квартала). Если в реальных данных одинаковый app_title может встречаться не подряд — это отдельный открытый вопрос (см. раздел 5, пункт 1).

## 3. Геометрическая модель слайда

- Слайд = сетка из ровно 4 фиксированных слотов по ширине (slot_width = table_width / 4).
- Каждый квартал занимает 1 или более слотов подряд слева направо, в порядке q1 → q2 → q3 → q4.
- Слот = вертикальный контейнер фиксированной ширины и фиксированной высоты (container_height), в который построчно укладываются ячейки фич.
- Исключение: если весь roadmap тира помещается на одном слайде и каждый показанный
  квартал занимает ровно один слот (нет подколонок), используемые колонки равномерно
  заполняют `table_width`: 1 → 100%, 2 → 50/50, 3 → по 1/3, 4 → по 25%.
  При подколонках или слайде-продолжении применяется базовая сетка 4×25%.

### Расчёт высоты ячейки фичи (для вместимости)

```
chars_per_line = floor(slot_width_in_chars(font_size, cell_padding))
line_count = ceil(len(feature.name) / chars_per_line)
cell_height = line_count * line_height + cell_vertical_padding
```

`chars_per_line` и `line_height` берутся из стилей эталонного шейпа-ячейки (шрифт, кегль, отступы) — их нужно считать программно из шаблона, а не хардкодить.

## 4. Алгоритм упаковки (packing)

### Шаг 1 — упаковка фич внутри квартала в под-колонки

```
для каждого квартала q (в порядке q1..q4):
    groups = сгруппировать features[q] по app_title, сохраняя порядок JSON
    подколонки = [новая пустая подколонка]
    для каждой group в groups:
        group_height = сумма cell_height всех features в group
        если group_height > container_height:
            # группа сама по себе не влезает целиком — см. открытый вопрос 2
            принудительно разбить группу построчно на подколонки (fallback)
        иначе если текущая_подколонка.высота + group_height > container_height:
            подколонки.append(новая пустая подколонка)
        текущая_подколонка.добавить(group)
    quarter.slot_count = len(подколонки)
```

Результат шага 1: для каждого квартала известно точное число требуемых слотов (`slot_count`) и распределение фич по под-колонкам.

### Шаг 2 — распределение кварталов по слайдам (по 4 слота на слайд)

```
слайды = [новый слайд с 4 свободными слотами]
для каждого квартала q (в порядке q1..q4):
    текущий_слайд = слайды[-1]
    если q.slot_count > 4:
        # квартал сам по себе больше целого слайда — см. открытый вопрос 3
        разбить q на несколько слайдов по 4 слота каждый, начиная с нового слайда
        продолжить со следующего квартала
    иначе если текущий_слайд.свободных_слотов < q.slot_count:
        текущий_слайд = новый слайд с 4 свободными слотами
        слайды.append(текущий_слайд)
    текущий_слайд.разместить(q, начиная со следующего свободного слота)
```

Важно: квартал никогда не разбивается между текущим и следующим слайдом частично — либо влезает целиком в остаток текущего слайда, либо целиком переезжает на новый (правило "весь квартал целиком").

## 6. доп требования к рендерингу

1. **Неконсекутивные группы app_title.** Если в JSON фичи одного продукта в пределах квартала идут не подряд (например, чередуются с другим продуктом), группировать ли их всё равно в одну атомарную группу 
2. **Группа выше высоты целой колонки.** Если у одного продукта фич так много (или тексты такие длинные), что группа не помещается целиком даже в один пустой слот — разрешаем принудительный разрыв этой группы (fallback)
3. **Квартал больше одного слайда.** Если после расщепления кварталу нужно больше 4 под-колонок (то есть он один не помещается на слайд из 4 слотов) — квартал может растянуться на несколько слайдов подряд (по 4 слота на слайд, только этот квартал) то на этих доп слайдах нужно показывать имя квартала
